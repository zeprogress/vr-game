# VR MMORPG — План разработки

> Пет-проект. Соло-разработчик. Цель: VR MMORPG с общим миром, в который можно
> зайти из VR (Quest 2/3, приоритет), из браузера на десктопе (вид от первого лица)
> и с телефона.

---

## 1. Ключевые решения

- **Один клиент на все устройства.** Три источника ввода (VR-контроллеры / клава+мышь /
  тач) сводятся к общему интерфейсу. Геймплейный код не знает, какое устройство.
- **Авторитетный сервер с самого начала (с этапа 4).** Клиент только рисует, сервер
  решает, что произошло. Бой, урон, лут, движение мобов — считает сервер.
- **Одна зона-комната**, не бесшовный мир. «Открытый мир» = позже несколько зон с
  переходами.
- **`shared/` — единственный источник правды** про числа (урон, скорости, радиусы,
  тайминги). Импортируют и клиент, и сервер.

## 2. Стек

| Слой | Технология | Почему |
|---|---|---|
| Язык везде | TypeScript | Один язык клиент+сервер, типобезопасность |
| Движок клиента | Babylon.js 7 | Лучший WebXR из коробки, работает в браузере Quest / десктоп / телефон из одной сборки |
| Сборка клиента | Vite | Быстро, минимум конфигурации |
| Сетевой сервер | Colyseus (Node.js) | Комнаты = зоны, бинарная синхронизация состояния, до десятков игроков. Огромная экономия времени для соло-разработчика |
| БД (сейчас) | SQLite + Prisma | Файл на ПК, ноль настройки |
| БД (потом) | PostgreSQL | Prisma меняет provider одной строкой |
| Кэш/сессии (потом) | Redis | Только когда >1 сервера зон |
| Доступ извне при тесте | Cloudflare Tunnel | Пустить друга на свой ПК-сервер без проброса портов |
| Хостинг потом | VPS + Docker | ~€5–15/мес |

**Почему не Unity/Godot:** WebGL-экспорт тяжёлый и медленно грузится в браузере Quest,
капризен с WebXR. Чистый веб-движок = «везде из одной ссылки» без боли.

## 3. Структура репозитория (целевая, монорепо)

```
vr-game/
  PLAN.md
  shared/                 # общий код клиент<->сервер
    src/
      protocol.ts         # типы сообщений
      constants.ts        # скорость бега, урон, тайминги
      schema/             # Colyseus-схемы состояния (Player, Mob, Loot)
      math/               # хелперы векторов
  client/
    src/
      main.ts
      engine/             # инициализация Babylon, рендер-луп
      input/              # <-- КЛЮЧЕВОЕ: абстракция ввода
        InputSource.ts    # интерфейс: move, look, primaryAction...
        DesktopInput.ts   # клава+мышь
        TouchInput.ts     # экранные стики
        XRInput.ts        # VR-контроллеры
      camera/             # риги камеры под каждый режим
      net/                # клиент Colyseus, интерполяция
      entities/           # визуальное представление игроков/мобов
      world/              # загрузка зоны, коллизии
      ui/                 # чат, HUD, health bar
  server/
    src/
      index.ts
      rooms/ZoneRoom.ts   # одна зона мира
      systems/            # серверная логика (тик 20 Гц)
        MovementSystem.ts
        MobAISystem.ts
        CombatSystem.ts
        LootSystem.ts
      persistence/        # Prisma
      db/schema.prisma
```

> **Сейчас (вариант B)** репозиторий — это просто один Vite-проект в корне
> (`src/`, `index.html`). Реструктуризация в монорепо — на этапе 4, когда добавим
> сервер. Так меньше движущихся частей на старте.

## 4. Архитектура сети

```
Клиент                          Сервер (авторитет, тик 20/сек)
------                          -------------------------------
ввод игрока  ──────────────────▶ применяет ввод к состоянию
                                 симулирует мобов, бой, лут
рисует мир  ◀────────────────── шлёт дельту состояния
интерполирует чужих игроков
предсказывает своё движение (client-side prediction, этап 5+)
```

- Попадания в бою считает сервер. Клиент показывает эффект сразу, урон подтверждает сервер.
- Чужие сущности рисуются с задержкой ~100 мс + интерполяция — выглядит плавно.

## 5. Абстракция ввода

```ts
interface InputState {
  moveVector: Vector2;      // WASD / тачстик / VR-стик
  lookDelta: Vector2;       // мышь / палец / поворот головы
  primaryAction: boolean;   // ЛКМ / кнопка / trigger
  interact: boolean;        // E / кнопка / grip
}
```

- **Desktop:** WASD + мышь (pointer lock), ЛКМ — атака.
- **Touch:** два виртуальных джойстика + кнопки поверх canvas, автоприцел.
- **VR:** левый стик — движение, правый — snap-turn, trigger — атака, grip — взять. Голова = камера.

## 6. Поэтапный план

### Этап 0 — Основы (1–3 недели, обучение)
- Node.js, VS Code, Git.
- Babylon.js Getting Started + «Build a house».
- Пустая сцена на GitHub Pages, открыть с телефона и Quest.

### Этап 1 — Одиночный «ходячий скелет», десктоп ✅ ГОТОВО
- Персонаж-капсула, WASD, mouse-look (pointer lock).
- Коллизии со стенами/землёй, гравитация.
- Простая зона: пол + препятствия.
- **Результат:** бегаешь по зоне от первого лица в браузере.

### Этап 2 — Абстракция ввода + камеры ✅ ГОТОВО
- Вынести ввод в `InputSource`.
- `TouchInput` + экранные стики → проверить на телефоне.

### Этап 3 — VR-режим ✅ ГОТОВО (проверено на Quest)
- `WebXRDefaultExperience`, кнопка «Enter VR».
- Движение стиком + snap-turn (и teleport как опция от укачивания).
- Тест на Quest 2/3.

### Этап 4 — Сервер и мультиплеер-движение ✅ ГОТОВО
> 4a репо, 4b Colyseus, 4c вход по нику, 4d синхр. позиций, 4e интерполяция,
> 4f share.command (Cloudflare Tunnel). Мобы/манекены — client-side до этапа 6.
- Colyseus, одна `ZoneRoom`. Реструктуризация в монорепо.
- Гостевой вход: ник → сервер создаёт `Player`, токен в localStorage.
- Синхронизация позиций, интерполяция чужих.
- Cloudflare Tunnel → тест вдвоём с разных устройств.

### Этап 5 — Сохранение прогресса ✅ ГОТОВО
> JSON-файл (не Prisma) src/server/.data/players.json по гостевому токену.
> Прогресс считает клиент, сервер хранит; серверный сейв главнее онлайн.
- Prisma + SQLite. `Account`(guestToken), `Character`(name, xyz, level, xp, hp).
- Автосейв раз в 30 сек + сейв при выходе.

### Этап 6 — Мобы и серверный AI ✅ ГОТОВО
- `ZoneSim` (без Babylon) на сервере: спавн, idle → chase → attack → dead → respawn
  для слизней и плевунов, полёт плевков. Тик 20 Гц в `ZoneRoom`.
- Общий `src/shared/terrain.ts` — рельеф сервера и клиента совпадает.
- Мобы/куклы/плевки в состоянии; `Mob`/`Dummy` на клиенте стали видом
  (сглаживание, вспышки, раны, звуки). `NetMobs` — менеджер вида.
- Попадание игрока считает клиент → `hm` → сервер применяет. Опыт — `xp`,
  урон по игроку — `mh` (щит/меч гасят на клиенте). Мобов нет в офлайне.
- Осталось на этап 7: серверная проверка геометрии попаданий.

### Этап 7 — Боёвка (3–4 недели)
- Серверная проверка попаданий: конус/сфера перед игроком, кулдаун, урон из `shared`.
- HP, смерть, респаун игрока и моба. XP и уровни.
- Клиентские эффекты мгновенно + подтверждение сервером.

### Этап 8 — Лут и инвентарь (2 недели)
- Моб умер → `LootDrop` в мире → «подобрать» → инвентарь в БД.
- UI инвентаря (сетка).

### Этап 9 — Чат (1 неделя)
- Colyseus-сообщения, локальный чат зоны, UI. В VR — панель на запястье.

### Этап 10 — PvP (1–2 недели)
- Флаг/зоны PvP, тот же `CombatSystem` с целью-игроком.

### Этап 11 — Перенос на VPS (1 неделя)
- Dockerfile сервера, статика клиента на CDN/Pages.
- SQLite → Postgres (Prisma migrate).
- Домен + HTTPS (обязательно для WebXR).

## 7. Подводные камни

1. **WebXR требует HTTPS.** Локально `localhost` ок, по сети — только туннель/сертификат.
2. **Браузер Quest слаб.** <100k полигонов в кадре, <50 мешей, простые шейдеры.
3. **Укачивание в VR.** Дать teleport + snap-turn на выбор.
4. **Тач в 3D-экшене неудобен.** Автоприцел / область атаки, не точное наведение.
5. **Не делать бесшовный мир сразу.** Одна зона-комната.
6. **Авторитет сервера с начала.** Переделка client→server authoritative = переписать половину.
7. **`shared/` дисциплина.** Любое общее число — только там.

## 8. Оценка сроков

MVP (этапы 1–9) при работе по вечерам в одиночку: **6–12 месяцев**. Это нормально.

## MVP (определение готовности)

Одна зона, 1–5 игроков в общем мире, вход из VR и из браузера, беготня + чат +
простая боёвка по мобам + подбор лута + сохранение прогресса.
