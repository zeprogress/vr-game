# Задача: реализовать HUB Blockout v1 — «Боевой лагерь»

Ты работаешь в существующем проекте VR MMORPG.

## Контекст проекта

Это браузерная MMORPG на:

- TypeScript
- Babylon.js 7
- Vite
- Colyseus / Node.js
- одна `ZoneRoom`
- VR через WebXR
- Desktop через keyboard + mouse
- Mobile через touch

Главный приоритет устройства: Quest 2/3.

Проект уже имеет рабочие:

- multiplayer movement;
- server-authoritative state;
- Mob AI;
- Combat;
- player HP/death/respawn;
- XP/levels;
- loot;
- inventory;
- weapons;
- voice chat;
- PvP;
- persistent player data;
- existing monster meadow;
- existing GLB asset loader/cache;
- day/night cycle.

Не переписывай эти системы.

Не создавай новый движок или новый способ загрузки мира.

Не создавай отдельную игру для хаба.

---

# Главная цель

Добавить в существующую игровую зону новый HUB — безопасный боевой лагерь.

Игрок должен иметь возможность:

```text
SPAWN
↓
увидеть лагерь
↓
взять оружие
↓
потренироваться
↓
осмотреться / пообщаться
↓
выйти через ворота
↓
по короткой дороге попасть на существующую поляну
↓
сражаться с существующими мобами
↓
вернуться обратно в лагерь
```

Хаб должен восприниматься как физическое место мира, а не как меню.

Очень важно:

**не создавать loading screen между HUB и MEADOW.**

HUB и MEADOW должны находиться в одной существующей `ZoneRoom`.

# 3. Размер HUB

Создай область приблизительно:

```ts

```



# 7. Safe Zone

Создай server-authoritative безопасную область хаба.

При нахождении игрока в HUB:

```text
mob damage = disabled
mob aggro = disabled
player PvP = disabled
```

Не меняй существующий PvP механизм глобально.

Добавь проверку зоны.

Например:

```ts
HUB_SAFE_RADIUS = 35
```

Но если форма лагеря лучше описывается прямоугольником/полигоном — используй подходящую геометрию.

Проверка должна выполняться на сервере.

Клиент не должен иметь возможность сам объявить себя безопасным.

# Формат работы

Работай небольшими этапами.

После каждого крупного изменения:

1. покажи изменённые файлы;
2. кратко объясни, что изменено;
3. проверь TypeScript/build;
4. исправь ошибки;
5. не переходи к следующему крупному этапу, пока текущий код не собирается.

Начни с анализа существующего проекта и предложи минимальный набор изменений для HUB Blockout v1.

После анализа сразу реализуй первый вертикальный срез:

**ground + central plaza + spawn points + gate + path to existing meadow.**
