# Лаборатория ZEP GAME

Лаборатория — отдельные сцены для проверки механик **до** деплоя. С 2026-11-03 у неё один
источник данных с игрой: числа и формулы берутся из `src/shared/*`, эффекты — из тех же
обработчиков, что в бою, а список умений — из `CLASSES2`.

## Веб: `npm run lab`

Открывает `lab.html` на `:5173`. Сцены выбираются в списке сверху; каждая перезагружает
страницу (`?s=<id>`), чтобы стартовать с чистого состояния.

| Сцена | Что проверяет |
|---|---|
| `?s=classes` | Баланс и DPS классов на манекенах. Визуал здесь упрощённый. |
| `?s=skills` | **Полигон умений:** все умения всех классов и их настоящий визуал. |
| `?s=fx` | Эффекты умений мобов/классов по кнопкам. |
| `?s=models`, `?s=trees`, `?s=dungeon`, `?s=fire` | Модели, деревья, подземелье, огонь. |

### Полигон умений (`?s=skills`)

- Класс, уровень, тир оружия, два кинжала, режим оружия (щит / один меч / два клинка), цель.
- Каждая карточка — умение класса: откат, урон, описание и кнопка **▶**.
- **Показать все** проигрывает все умения класса подряд; **Проверить сценарии** сверяет
  покрытие и печатает, каких эффектов не нашлось.
- Ссылки для проверки: `?s=skills&cls=archer&skill=blastArrow&level=50&repeat=1`.
  `repeat=1` повторяет умение каждые 2.2 с — удобно ловить момент эффекта.

Числа на карточках считают те же функции, что окна умений и сервер:

- откат — `skillCooldownFor` (`shared/classes2.ts`), с классом и МДР;
- урон — `skillStrike` + `skillDamageText` (`shared/strike.ts`, `shared/skillDamage.ts`);
- описание — `skillDesc` (с подстановкой `{d:...}`/`{r:...}`);
- радиус/длительность/число ударов — `SKILLS2` и константы умений.

Визуал: сценарий `shared/skillShow.ts` (что, где и через сколько секунд) проигрывают
**настоящие** обработчики `ClassFx.playClassAct`, `playSteelAct`, `playDrawAct` и `SkillFx`.
Никаких «своих» колец и цифр в лаборатории нет.

### Как добавить умение

1. Добавить `SkillId` и запись в `SKILLS2`, классу — в `CLASSES2[...].skills`.
2. Добавить ветку в `shared/skillShow.ts` (иначе тест `skillShow` упадёт и карточка
   станет красной: «НЕТ СЦЕНАРИЯ»).
3. `npm test` — проверяет покрытие всех пар «класс × умение».
4. Для Unity: `npm run lab:unity` (см. ниже).

## Unity: полигон умений

Данные для Unity генерируются из того же `skillShow.ts`:

```bash
npm run lab:unity     # пишет unity/Assets/Resources/skillLab.json
```

В Unity:

- **Zep → Open Skills Lab** — открыть `Assets/Scenes/Lab.unity` (при отсутствии соберёт).
- **Zep → Build Skills Lab** — пересобрать сцену.
- Play: справа пульт — классы, список умений, «Показать все». ПКМ — камера, колесо — дистанция.
- Эффекты играет общий `ClassActs.Play` / `BossActs.Play` — тот же обработчик, что в игре и
  спектаторе. Сеть не нужна: `ZoneNet.offline = true`.

Если в `CLASSES2` изменился список умений, а JSON не пересобрали, тест
`tests/shared/unitySkillLab.test.ts` упадёт: Unity-полигон не должен молча отставать.

## Что проверять глазами

- Совпадает ли момент удара с клипом (замах → удар → след), нет ли эффекта «до» клипа.
- Виден ли радиус/зона на земле и не закрывает ли он бой.
- Не остаются ли висеть кольца/декали после конца умения.
- Для лучника — летят ли настоящие стрелы, для воина — ходит ли аура за героем, для
  боевого мага — бьёт ли молния в конце вихря.
- На Quest/телефоне — нет ли просадки fps на самом тяжёлом умении класса.
